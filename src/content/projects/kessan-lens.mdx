## Problem

Japanese companies file their annual and quarterly securities reports with the
Financial Services Agency's EDINET system as XBRL. The data is public and free,
but it is organised by filing rather than by company, and account titles are in
Japanese. Comparing five years of a company's statements, or two peers, in
English takes real effort.

## Approach

- **Ingest:** a nightly Java ETL pulls new filings from the EDINET API v2
  (incremental pulls only; EDINET does not allow bulk downloads).
- **Normalise:** account titles get their English names from the Financial
  Services Agency's own English labels, which every standard account has.
  Company-specific accounts without one keep their Japanese name, marked as such.
- **Serve:** five-year statements in Japanese, English or both, with ratios,
  peer comparisons and CSV downloads that carry the source attribution.
- **Test:** JUnit and Mockito for the ETL, with a real database container in CI.

## Architecture

Recommended in the planning research, not yet decided: a hexagonal Java 17 core
with a nightly Spring Boot batch job, MyBatis over Postgres as the system of
record, and a static read model served from Cloudflare Pages, with a read-only
Java API later. Customisations for EDINET: incremental, rate-limited pulls only,
a bilingual label layer, and a fallback to the Japanese name wherever an English
label is missing.

## Where it stands

Planning done on 2026-10-21: research on EDINET's API and licences, architecture
options and open questions are written up. On hold while another project goes
first; no code yet.

Known limitations to design for: EDINET forbids bulk downloads, so the
history fills in gradually; the EDINET taxonomy may be shown only unmodified,
with the FSA's copyright notice; quarterly figures after April 2024 are
published only on TDnet, which forbids redistribution, so the first version
covers annual reports; and company-specific elements can lack an English label.
